# Reproducibility

## Environment

Tested with:
- Python 3.14.5 (anything 3.10 or newer should work)
- pennylane 0.45.1
- numpy 2.5.1
- scipy 1.18.0
- matplotlib 3.11.1
- psutil 7.2.2

No `torch` dependency anywhere in this repo. `frequency_unit_conversion.py` deliberately uses PennyLane's own autodiff (`qp.jacobian`/`qp.grad`) instead, since that's what the rest of the codebase (`pde_residual()`) is already built on.

`barren_plateau_control.py`, `gradient_conflict.py`, and `fisher_effective_dimension.py` add no dependencies either — the least-squares fit in the first is written out longhand rather than pulling in `polyfit`/`scipy`, so everything runs on the same PennyLane-plus-numpy install.

Install with:
```python
pip install pennylane numpy scipy matplotlib psutil
```
All scripts assume they're run from `SPECops/src/`. They resolve `results/` and `sweep_checkpoints/` relative to their own file location, not the current working directory, so this isn't strictly required, but the paths below assume it anyway. `checkpoint.py` is a tiny shared helper (`saveCheckpoint`/`loadCheckpoint`, a pickled `{params, config}` dict) that nearly every script below imports. It has no `__main__` of its own, so there's nothing to run directly in that file.

## Known issue: MemoryError under process contention

`q5_r5` (and generally anything with a high `n_qubits` combined with a high `n_reuploads`, meaning circuit depth) can throw a `MemoryError` even with only one or two other scripts running at the same time. It's not purely a matter of how many processes are running; the deep-circuit configs are specifically the ones that tip it over. This isn't limited to the quantum scripts either, the classical scripts aren't exempt.

This has bitten the project a few times now, an extended-training run and a heat-equation sweep pass among them, so every script added since has settled on the same two-part workaround: train one config per process (don't loop over a whole grid inside one long-lived process, since that leaks PennyLane device and qnode state between configs and makes things worse, not better), and retry once or twice on `MemoryError` specifically before giving up on that config.

`heat_equation_sweep.py`, `extend_training.py`, `entanglement_variation.py`, and `measurement_operator_variation.py` all build the retry in themselves. The `run_*.sh` scripts add an outer retry-and-log loop on top for the configs that get orchestrated from the shell instead of called directly.

## Output file glossary

- `sweep_results.csv` — per-seed accuracy/timing rows for the quantum sweep. Columns: `n_qubits, n_reuploads, seed, l2_error, pde_residual_error, final_train_loss, train_time_sec, param_count, peak_memory_mb`. Aggregate mean/std per config from these rows directly (grouped by `n_qubits, n_reuploads`) — the script no longer writes a pre-aggregated row.
- `classical_comparison.csv` — same metrics as above but pre-aggregated (mean/std across seeds) for the non-quantum control architecture, for a direct comparison against any sweep config.
- `gradient_variance_results.csv` — barren-plateau check: variance of `d(pde_loss)/d(W_q)` across 50 random inits per config, on a fixed collocation batch. Decreasing toward zero as `n_qubits` grows is the barren-plateau signature.
- `barren_plateau_control.csv` / `barren_plateau_control_fit.json` — the control for `gradient_variance_results.csv`. Variance of `∂⟨H⟩/∂θ₁₁` across random inits of a random parameterised circuit (McClean et al. 2018, Fig. 2), at qubit counts 2–8 with depth `2n`, plus the least-squares fit of `ln(Var)` against qubit count. The published slope is −1.374 for `H = |0…0⟩⟨0…0|`; note their plots are in natural log, not log10, which is a factor of 2.303 waiting to be misread. A passing fit is what licenses reading a *flat* `gradient_variance_results.csv` as "no plateau here" rather than "estimator can't see one". The CSV is appended to, so a run with `--also-sweep-grid` leaves a duplicate `n_qubits=4` row from the two overlapping sweeps — the fit JSON covers only the 2/4/6/8 control sweep.
- `fourier_spectrum_results.csv` — the set of integer frequencies each config's circuit can represent, in units of the encoding angle (post pre-layer tanh), not physical `x`.
- `burgers_shock_spectrum.json` — the actual spatial frequency content of the Burgers' shock (from the exact Cole-Hopf solution), in physical `x` units, at `t ∈ {0.1, 0.3, 0.5, 0.7, 0.9}`.
- `frequency_unit_conversion.csv` / `expressivity_vs_shock.csv` — bridges the two units above via the pre-layer's local slope, then checks whether each config's frequency ceiling (in physical-x units) is sufficient to represent the shock's required bandwidth at each snapshot.
- `activation_analysis.csv` — mean/std of pre-layer, post-quantum-layer, and final output activations for a trained classical vs. quantum checkpoint, evaluated on the same `(t,x)` grid. Gets overwritten by `activation_diversity.py` with a 12-config-plus-classical superset — check which script produced the copy on disk before trusting row count.
- `activation_diversity.csv` — across-neuron variance and mean pairwise correlation of activations per config/layer. Low mean pairwise correlation = neurons carrying distinct information; high = redundant. This is the core "redundancy" metric referenced throughout the later sections.
- `activation_measurement_check.csv` — same-observable (PauliZ x n) vs. mixed-observable (Z/X/Y cycling) neuron-mean spread per config, checking whether post-quantum-layer uniformity is a measurement artifact or a property of the underlying state.
- `effective_rank.csv` — entropy-based effective rank (Roy & Vetterli 2007) of the post-quantum-layer output matrix per config. Max possible value is `n_qubits`; near-max means the layer's outputs are close to linearly independent (high information content), near-1 means they're all pointing the same way.
- `sweep_results_stratified.csv` — L2 error split into "smooth" (`t<0.3`) and "shock" (`t>=0.5`) buckets per checkpoint, from `stratified_eval.py`.
- `heat_equation_sweep.csv` — same columns as `sweep_results.csv` but for the heat-equation cross-validation PDE (linear, no shock) instead of Burgers'. Columns: `n_qubits, n_reuploads, seed, l2_error, pde_residual_error, train_time_sec`.
- `heat_equation_redundancy.csv` — `activation_diversity.csv`'s metrics, computed on the heat-equation checkpoints instead of the Burgers' sweep.
- `longer_training_results.csv` — from `extend_training.py`: one row per eval checkpoint of a continued-training run past the original 100 epochs. Columns include `total_epochs` (absolute epoch count, not epochs-since-continuation) and `wall_clock_elapsed_sec` (cumulative since that `extend_training.py` invocation started, not since the original checkpoint was first trained).
- `q5_r5_adam_convergence.csv` / `classical_matched_adam_convergence.csv` (general pattern: `{tag}_convergence.csv`) — from `train_adam.py`, a row per eval checkpoint of an Adam-optimized run. Written live throughout training, not just at the end, so a killed run still leaves a usable partial curve.
- `flatness_check.csv` — total variation, mean abs gradient, and amplitude range of a trained config's prediction surface vs. the Cole-Hopf reference, checking whether a low-residual/low-accuracy config got there by collapsing toward a flat solution.
- `shapley_subset_l2.csv` / `shapley_layer_attribution.csv` — from `shapley_layer_attribution.py`: L2 error for every active-re-upload-layer subset, and the resulting exact Shapley value per layer. Shapley values should sum to the full-circuit-vs-empty-circuit L2 gap (printed as a sanity check when the script runs).
- `entanglement_variation.csv` — L2/residual/redundancy for q5_r5 under ring (main.py's default), linear, and no-entanglement circuit topologies. `retrained` is `False` for ring (reuses the existing sweep checkpoint) and `True` for the other two.
- `measurement_operator_variation.csv` — L2/residual/param-count for the default PauliZ readout vs. an all-wires `qml.probs()` readout. The probs variant has a different post-layer input size (2^n_qubits vs n_qubits) so its param count isn't matched to the baseline — see the `notes` column.
- `measurement_operator_redundancy.csv` — the same redundancy metrics again, on the probs-measurement checkpoint. Not shape-comparable to the PauliZ-based redundancy numbers elsewhere (different output dimensionality).
- `redundancy_over_epochs.csv` — mean pairwise correlation and effective rank for q3_r1 and q5_r5, snapshotted at epochs 100/300/500, to see whether the redundancy signature is present from the start of training or develops over it.
- `loss_landscape_slice.csv` — loss along 3 random filter-normalized directions (Li et al. 2018) through the converged q5_r5 minimum, at 21 alpha values each from -1 to 1.
- `gradient_conflict.csv` — cosine between the data-term and residual-term gradients per config, at random init and (where a checkpoint exists) at the trained minimum. `cos_all_params` covers every parameter; `cos_wq_only` covers the quantum layer alone. `norm_ratio_data_over_residual` says which term dominates the update magnitude — far from 1 means the smaller term is effectively ignored regardless of direction. Negative cosine means the two terms are actively cancelling on the shared parameters, which looks like a vanishing gradient in a training curve but has the opposite fix (reweight the loss, not change the ansatz). Individual signs are noisy at the default `--n-f-batch 5`; the stable reading is the ordering `cos_wq_only < cos_all_params`, which held across all 12 configs.
- `fisher_effective_dimension.csv` — `fisher_entropy_rank` is the Roy & Vetterli entropy rank of the parameter-space Fisher (same definition `effective_rank.py` uses on activations, different matrix). `rank_utilisation` is that divided by `n_params`, i.e. what fraction of the nominal parameter count moves the model at all — the column to read directly next to `param_count` in `sweep_results.csv`. `normalised_effective_dimension` is the Abbas et al. quantity, comparable across configs with different parameter counts, which raw rank is not. Rows with `state = random_init` are the weaker version of the claim: at initialisation the model is close to linear, so low rank is partly expected — the trained rows are the ones to quote.

## Output file glossary

- `sweep_results.csv`: per-seed accuracy and timing rows for the quantum sweep. Columns: `n_qubits, n_reuploads, seed, l2_error, pde_residual_error, final_train_loss, train_time_sec, param_count, peak_memory_mb`. Aggregate mean/std per config from these rows directly (grouped by `n_qubits, n_reuploads`); the script no longer writes a pre-aggregated row.
- `classical_comparison.csv`: same metrics as above but pre-aggregated (mean/std across seeds) for the non-quantum control architecture, for a direct comparison against any sweep config.
- `gradient_variance_results.csv`: barren-plateau check, variance of `d(pde_loss)/d(W_q)` across 50 random inits per config, on a fixed collocation batch. Decreasing toward zero as `n_qubits` grows would be the barren-plateau signature.
- `fourier_spectrum_results.csv`: the set of integer frequencies each config's circuit can represent, in units of the encoding angle (post pre-layer tanh), not physical `x`.
- `burgers_shock_spectrum.json`: the actual spatial frequency content of the Burgers' shock (from the exact Cole-Hopf solution), in physical `x` units, at `t` in {0.1, 0.3, 0.5, 0.7, 0.9}.
- `frequency_unit_conversion.csv` / `expressivity_vs_shock.csv`: bridges the two units above via the pre-layer's local slope, then checks whether each config's frequency ceiling (in physical-x units) is sufficient to represent the shock's required bandwidth at each snapshot.
- `activation_analysis.csv`: mean/std of pre-layer, post-quantum-layer, and final output activations for a trained classical vs. quantum checkpoint, evaluated on the same `(t,x)` grid. Gets overwritten by `activation_diversity.py` with a 12-config-plus-classical superset; check which script produced the copy on disk before trusting the row count.
- `activation_diversity.csv`: across-neuron variance and mean pairwise correlation of activations per config/layer. A low mean pairwise correlation means neurons are carrying distinct information; a high one means they're redundant. This is the core redundancy metric referenced throughout the later sections of the report.
- `activation_measurement_check.csv`: same-observable (PauliZ times n) vs. mixed-observable (Z/X/Y cycling) neuron-mean spread per config, checking whether post-quantum-layer uniformity is a measurement artifact or a property of the underlying state.
- `effective_rank.csv`: entropy-based effective rank (Roy and Vetterli, 2007) of the post-quantum-layer output matrix per config. The maximum possible value is `n_qubits`; a value near that max means the layer's outputs are close to linearly independent (high information content), and a value near 1 means they're all pointing the same way.
- `sweep_results_stratified.csv`: L2 error split into "smooth" (`t<0.3`) and "shock" (`t>=0.5`) buckets per checkpoint, from `stratified_eval.py`.
- `heat_equation_sweep.csv`: same columns as `sweep_results.csv` but for the heat-equation cross-validation PDE (linear, no shock) instead of Burgers'. Columns: `n_qubits, n_reuploads, seed, l2_error, pde_residual_error, train_time_sec`.
- `heat_equation_redundancy.csv`: the same metrics as `activation_diversity.csv`, computed on the heat-equation checkpoints instead of the Burgers' sweep.
- `longer_training_results.csv`: from `extend_training.py`, one row per eval checkpoint of a continued-training run past the original 100 epochs. Columns include `total_epochs` (absolute epoch count, not epochs-since-continuation) and `wall_clock_elapsed_sec` (cumulative since that `extend_training.py` invocation started, not since the original checkpoint was first trained).
- `q5_r5_adam_convergence.csv` / `classical_matched_adam_convergence.csv` (general pattern: `{tag}_convergence.csv`): from `train_adam.py`, a row per eval checkpoint of an Adam-optimized run. Written live throughout training, not just at the end, so a killed run still leaves a usable partial curve.
- `flatness_check.csv`: total variation, mean absolute gradient, and amplitude range of a trained config's prediction surface vs. the Cole-Hopf reference, checking whether a low-residual, low-accuracy config got there by collapsing toward a flat solution.
- `shapley_subset_l2.csv` / `shapley_layer_attribution.csv`: from `shapley_layer_attribution.py`, L2 error for every active-re-upload-layer subset, and the resulting exact Shapley value per layer. The Shapley values should sum to the full-circuit-vs-empty-circuit L2 gap (printed as a sanity check when the script runs).
- `entanglement_variation.csv`: L2, residual, and redundancy for q5_r5 under ring (`main.py`'s default), linear, and no-entanglement circuit topologies. `retrained` is `False` for ring (reuses the existing sweep checkpoint) and `True` for the other two.
- `measurement_operator_variation.csv`: L2, residual, and parameter count for the default PauliZ readout vs. an all-wires `qml.probs()` readout. The probs variant has a different post-layer input size (2^n_qubits vs. n_qubits), so its parameter count isn't matched to the baseline; see the `notes` column.
- `measurement_operator_redundancy.csv`: the same redundancy metrics again, on the probs-measurement checkpoint. Not shape-comparable to the PauliZ-based redundancy numbers elsewhere, since the output dimensionality differs.
- `redundancy_over_epochs.csv`: mean pairwise correlation and effective rank for q3_r1 and q5_r5, snapshotted at epochs 100, 300, and 500, to see whether the redundancy signature is present from the start of training or develops over the course of it.
- `loss_landscape_slice.csv`: loss along 3 random filter-normalized directions (Li, Xu, Taylor, Studer, and Goldstein, 2018) through the converged q5_r5 minimum, at 21 alpha values each, ranging from -1 to 1.
